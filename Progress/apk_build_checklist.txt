SECTION 3: ANDROID MANIFEST & PERMISSIONS [BLOCKER]
================================================================================
Your release APK is currently MISSING the INTERNET permission. Flutter only
adds it to debug/ and profile/ manifests, NOT to the main release manifest.
Without it, the release APK cannot make any network calls at all.

CHECKLIST:

[ ] 3.1  Add INTERNET permission to MAIN AndroidManifest.xml
         File: c:\HAT\client\android\app\src\main\AndroidManifest.xml
         Add BEFORE the <application> tag:

         <uses-permission android:name="android.permission.INTERNET"/>
         <uses-permission android:name="android.permission.ACCESS_NETWORK_STATE"/>

[ ] 3.2  If backend stays on HTTP (not HTTPS), add cleartext traffic flag
         In the same file, add to the <application> tag:

         android:usesCleartextTraffic="true"

         NOTE: If you deploy backend to Railway/Render (HTTPS), you do NOT
         need this flag. HTTPS is always preferred.

[ ] 3.3  Change app display name from "hat_client" to something user-friendly
         In AndroidManifest.xml, change:
           android:label="hat_client"
         To:
           android:label="HAT Hydroponics"

SECTION 4: APP SIGNING [REQUIRED]
================================================================================
Right now your release build uses the DEBUG signing key. This means:
  • Google Play Store will reject it if you ever want to publish
  • Some phones show "untrusted app" warnings more aggressively
  • You cannot update the APK later if you lose the debug keystore

CHECKLIST:

[ ] 4.1  Generate a release signing keystore (ONE TIME — save it forever):

         keytool -genkey -v -keystore hat-release-key.jks ^
           -keyalg RSA -keysize 2048 -validity 10000 ^
           -alias hat-key

         Store the .jks file and password somewhere SAFE (NOT in git).

[ ] 4.2  Create c:\HAT\client\android\key.properties:

         storePassword=<your-password>
         keyPassword=<your-password>
         keyAlias=hat-key
         storeFile=<full-path-to>/hat-release-key.jks

[ ] 4.3  Update build.gradle.kts to reference the keystore:
         File: c:\HAT\client\android\app\build.gradle.kts

         In the release buildType, replace:
           signingConfig = signingConfigs.getByName("debug")
         With a proper release signingConfig block.

[ ] 4.4  Add key.properties and *.jks to .gitignore (NEVER commit these)

SECTION 6: ESP32 WI-FI CONFIGURATION [REQUIRED for testers]
================================================================================
Right now the Wi-Fi credentials are HARDCODED in firmware:
  c:\HAT\firmware\src\main.cpp  (lines 48-49)
    WIFI_SSID     = "UCP"
    WIFI_PASSWORD  = "Ucp@987987"

This means the ESP32 ONLY works on the "UCP" network. If a tester takes the
hardware home, it won't connect.

SOLUTIONS (in order of effort):

  Option A (Quick): Keep hardcoded, just reflash for each test site
  Option B (Better): Use ESP32 WiFiManager library — creates a temporary
    hotspot ("HAT-Setup") on first boot. User connects with phone and
    enters their home Wi-Fi credentials. Saves to flash, survives reboots.
  Option C (Best): BLE provisioning from the Flutter app (future roadmap)

SECTION 9: BUILD THE APK
================================================================================

Once all items above are complete:

  COMMAND TO BUILD:
    cd c:\HAT\client
    flutter build apk --release

  OUTPUT FILE LOCATION:
    c:\HAT\client\build\app\outputs\flutter-apk\app-release.apk

  APK SIZE: Expected ~15-25 MB

  TO BUILD A SMALLER, SPLIT APK (per CPU architecture):
    flutter build apk --split-per-abi

  This creates 3 APKs:
    app-armeabi-v7a-release.apk    (~12 MB, older phones)
    app-arm64-v8a-release.apk      (~13 MB, modern phones — MOST COMMON)
    app-x86_64-release.apk         (~14 MB, emulators only)

  Give testers the arm64-v8a APK unless they have very old phones.
